# 校园信息系统整体流程与小组接入说明

更新于2026-11-16，适用4名DBA与15个业务组。本文为拟采用的统一集成方案，路径、凭证和部署约定均需在首批联调时共同确认。

## 1. 生命周期与协作方式

各组完成本模块的系统规划、分析、设计、实现、自测和课程文档。DBA贯穿全过程协调共享数据、统一身份、模块接入和最终部署。数据库建设、接口设计与前后端开发可并行推进，各组分批交付可运行版本，DBA持续联调。

规划分析阶段明确业务范围、服务身份和跨组依赖。设计阶段确认数据表、维护责任、权限和接口草案。实现阶段按共享演示数据开发。测试实施阶段验证权限、业务流程及联网部署。报告随阶段成果持续整理。

课程文档要求在2026-12-07 12:00前交DBA，阶段检查和演示时间按教师安排确认。

## 2. 数据方案

按一个共享MySQL数据库组织，各组使用独立数据库账号。当前分工参考《各组数据字典_单表美化审查版_字段协同修订.xlsx》，确认后再建表和授权。

| 角色 | 数据职责 |
| --- | --- |
| DBA | 建立数据库，提供接入和建表示例，管理账号、权限、备份恢复及结构变更记录 |
| 表的主维护组 | 建表，落实主键外键及业务约束，维护常规数据，提交初始化和变更SQL |
| 字段协同维护组 | 按确认字段和操作回写业务结果，提供同步规则与测试案例 |
| 数据提供组 | 提供权威身份、机构、学籍、课程或结果，由约定维护方引用或同步 |
| 使用组 | 在授权字段及记录范围内查询，按约定使用共享数据 |

浏览器通过业务后端访问数据库，数据库凭据通过后端配置提供。业务组负责选课容量、库存、多表事务、结果回写等业务一致性，DBA组织跨组核对。

当前汇总稿包含sys_user.user_id、student.student_id和t_employee.emp_id。平台账号与学生学籍、职工身份的对应关系须在首次联调前明确，字段类型与历史编号按字典待确认项映射。主维护组可在共享用户映射上绑定本模块业务身份。

## 3. 最终部署和联网

建议各组分别构建前端和后端，DBA统一部署，提供登录页和模块门户。

~~~mermaid
flowchart TD
    B[不同电脑的浏览器] --> E[统一HTTPS入口与反向代理]
    E --> P[登录页与15模块门户]
    E --> F[各组前端页面]
    E --> A[统一认证服务]
    E --> M[各组Spring Boot后端]
    M --> V[身份和业务权限校验]
    V --> D[共享云端MySQL]
    A --> D
~~~

部署时由DBA启动各模块后端并配置进程管理。用户点击模块卡片后，浏览器进入相应前端页面，页面调用已经运行的后端业务接口。前端入口路径、业务API和部署启动命令分别交付。

| 内容 | 建议路径 | 负责方 |
| --- | --- | --- |
| 登录页与门户 | /login、/portal | DBA |
| 统一认证接口 | /api/auth/ | DBA |
| 01组前端入口 | /modules/m01/ | 01组提供，DBA发布 |
| 01组业务API | /api/m01/ | 01组提供，DBA转发 |
| 其他组 | 对应m02至m15 | 各组与DBA |

各组前端配置Vite的base、前端路由基路径和接口地址。DBA配置模块子路径、深层路由回退和后端转发，共同验证页面刷新、静态资源、上传下载及跨页跳转。

联网运行通过不同电脑访问统一入口，应用服务经网络访问云端MySQL。最终节点布局与课程分布式要求对齐，服务器规格根据实际后端进程、内存、连接数和演示负载确定。

## 4. 统一登录和身份传递

当前建议采用同一HTTPS站点、统一认证服务、服务端会话与登录Cookie。

用户先选择学生、教师、辅导员或后勤等身份，再输入账号密码。认证服务同时核验账号、密码哈希、账号状态和所选身份授权，成功后建立会话。账号没有所选身份时返回登录失败。

认证服务由DBA开发为一个Spring Boot后端服务，访问共享数据库中的账号、角色关系和会话记录。账号信息包含唯一登录编号、登录名、密码哈希和状态，角色关系支持一个账号多个身份。平台用户与现有student.student_id、t_employee.emp_id等业务标识保持明确映射。名称允许重名，密码采用专用密码哈希算法。

成功登录后，服务端生成高随机性的会话凭证并记录用户、当前身份和有效期，通过Set-Cookie写入浏览器。统一Cookie名暂定CAMPUS_SESSION，正式HTTPS部署配置HttpOnly、Secure、SameSite=Lax和Path=/，使用当前站点的host-only范围。仅认证服务维护此Cookie，模块接入示例负责避免覆盖或冲突。

门户打开/modules/m01/时，浏览器按Cookie范围自动携带凭证。该页面随后请求同站点/api/m01/业务接口时，也会携带Cookie。各组后端接入DBA提供的认证过滤器，读取Cookie并通过仅供后端调用的会话核验接口确认会话，建立Spring Security认证上下文。该内部接口有独立的服务访问控制，返回最小身份信息。

核验结果包含登录用户编号、当前身份及所需的学生/职工映射。模块继续检查操作权限及本人、授课班、负责行政班等记录范围。凭证无效或过期返回401，已登录但缺少权限返回403。认证服务不可用时拒绝办理受保护业务。

模块页面可调用GET /api/auth/me获取显示用的当前身份。模块后端使用已验证的认证上下文决定数据访问。只携带Cookie无法让互相独立的Spring Boot服务自动共享会话，必须接入上述公共过滤器和会话核验服务。

退出登录由认证服务撤销服务端会话并清除Cookie。重新登录或切换身份撤销旧会话并创建新会话，防止旧身份继续使用。本阶段采用每次受保护请求核验会话，凭证失效可及时生效，后续再按实际负载评估短缓存。

Cookie认证同时启用CSRF防护。DBA提供前端请求封装和后端校验示例，写入请求携带CSRF令牌，并验证会话关联及请求来源。登录和退出同样按统一方案保护。用户直接通过链接打开页面不需要自行拼接身份或凭证。

本地开发通过统一示例配置Vite代理，将/api/auth/指向测试认证服务，将/api/m01/指向本组后端，保持浏览器侧同一开发来源。使用专门的测试Cookie名称与本地配置，正式环境统一HTTPS安全属性。正式服务地址、内部核验凭据和数据库密码通过后端配置提供。

## 5. 门户与模块权限

各组提交“身份—操作—数据范围”清单，DBA汇总模块访问矩阵。

| 身份示例 | 可办理操作示例 | 数据范围 |
| --- | --- | --- |
| 学生 | 选课、查询成绩 | 本人 |
| 教师 | 录入成绩 | 本人授课并有录入权限的教学班 |
| 辅导员 | 查看学籍、审核申请 | 所负责班级，按业务规则 |
| 后勤工作人员 | 办理后勤任务 | 本人任务或被授权组织 |
| 模块管理员 | 本模块管理 | 已授予的模块与组织范围 |

门户可将无访问资格的模块置灰并显示说明。直接访问模块URL或业务API时，各模块后端仍执行权限校验。401表示凭证无效或过期，403表示已认证但无当前操作权限。服务故障使用相应错误响应区分。

## 6. 必须共同确定的最小接入约定

| 项目 | 约定 | 责任 |
| --- | --- | --- |
| 模块前端入口 | /modules/m01/至/modules/m15/，模块有自己的首页及内部导航 | 各组提供，DBA发布 |
| 模块业务API前缀 | /api/m01/至/api/m15/，相对路径，反向代理保留前缀 | 各组实现本模块API，DBA配置转发 |
| 统一登录 | POST /api/auth/login，输入login_name、password、role，成功设置登录Cookie | DBA提供 |
| 当前身份 | GET /api/auth/me，返回验证后的用户及当前身份 | DBA提供，模块按需展示 |
| 统一退出 | POST /api/auth/logout，撤销会话并清除Cookie | DBA提供 |
| 后端身份核验 | 内部会话核验接口，由公共认证过滤器调用并建立当前用户上下文 | DBA提供组件，各组接入 |
| 请求防护 | 公共前端组件携带CSRF令牌，后端示例校验写入请求 | DBA提供，各组接入 |
| 部署交付 | 源码、前端dist、后端JAR、构建启动命令、版本及配置、上传目录 | 各组交付，DBA部署 |

以上路径为本次建议约定，首个模块联调后统一发布。门户通过模块入口进入各组页面，各组页面调用自己的业务API，DBA无需重写各组业务页面或逐项编排内部功能。

各组需要交付一个前端入口并适配统一认证，业务API通过各自前缀正常工作。若某项业务必须跨组执行，提供组与调用组再约定该项业务接口和结果回写。部署启动命令供DBA在服务器启动模块，后端持续运行。

每组接入登记只需注明组号、入口路径、API前缀、可用角色、角色对应的记录范围、启动配置及所依赖的库表。最终权限仍由该组后端逐请求执行。

## 8. 实施与验收

1. 确定前端框架及工具版本、账号身份映射、角色和业务范围、模块入口及API前缀。
2. DBA提供认证服务、联调账号、前后端接入样例和共享数据库接入说明。
3. 用01学籍与03选课成绩中的最小页面试通登录、模块跳转和数据查询，再接02开课走通业务。
4. 逐步接入其余模块，复测共享读写、协同回写、角色及记录权限，持续同步变更。
5. 统一部署后检查任意电脑访问、模块页面、直接子路径刷新、静态资源、上传下载、过期登录、退出、身份切换、401/403，以及跨组业务流程。
6. 冻结演示版本，备份数据库和配置，准备启动恢复说明与演示账号，各组核对文档和功能。

15个Spring Boot后端的资源需求需要实际测量。统一部署时采用明确的进程、端口和启动管理，连接池总量与云数据库规格配套。

## 9. 可发送给各组的说明

本次课程由各组按系统规划、分析、设计、实现和测试的生命周期完成本模块，DBA负责共享数据库、统一登录与门户，以及最后的联网部署和系统集成。

各组按下发并确认的数据字典建立主维护表，完成数据维护，按字段协同分工提供或回写结果。DBA会提供共享数据库连接方法、建表示例和权限说明。

各组开发自己的前端页面与Spring Boot后端，接入DBA提供的统一认证示例，完成本模块的角色、功能和记录范围校验。各组提交前端入口、业务接口文档、数据库脚本、配置及可复现的启动方法，并完成本机自测。

DBA统一部署前后端，提供一个登录入口和包含15模块的门户。用户登录并选择已获授权的身份后，进入模块继续办理业务，各组后端根据有效身份执行权限检查。模块后端由部署环境启动并持续运行，门户点击操作进入对应页面。

各组在开发期间分批提供可运行版本，与DBA共同联调，及时同步数据结构、接口和配置变更，完成全系统联网演示。

## 10. 技术依据与当前状态

Cookie由服务端设置，浏览器按域和路径等规则附带到后续请求。[MDN Cookie说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie)

Spring Security提供CSRF防护，前后端示例需适配Cookie认证和单页应用的令牌传递。[Spring Security官方文档](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)

Vite提供构建与子路径base设置。[Vite官方文档](https://vite.dev/guide/build.html)

Nginx支持HTTP后端转发。[Nginx官方文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)

本稿已对齐单库和字段协同方向。统一认证服务、门户与模块适配尚待实现。前端框架、版本、凭证生命周期及账号映射属于待共同确认的设计项。
